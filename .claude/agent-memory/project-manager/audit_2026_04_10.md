Full QA audit of all 4 user personas' flows on 2026-04-10.

**Why:** Client (Ariel Marcus) is testing the live app. Need to catch bugs before he does.

**How to apply:** These findings should be fixed in priority order before next client demo. Critical items block real usage.

Key findings:
- 2 `any` type violations in owner portal (staging photos)
- Task create uses client-side Supabase (works because of admin RLS policy, but creates server action duplication)
- Bill approve uses server action + separate client-side update for payment_method (race condition potential)
- Owner portal has no dedicated layout.tsx (no auth guard at layout level, relies on page-level redirect)
- Owner portal single-page architecture may feel cramped on mobile
- PWA icons exist but next-pwa not confirmed in next.config
- Messages don't use real-time subscriptions (manual polling only)
- No middleware match for /reports route
